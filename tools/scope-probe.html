drive.file scope probe

Does picking a folder with only the drive.file scope grant access to what is inside it? Decides issue #28.

What this actually tests, and why it is worth running

It requests only drive.file — never the restricted auth/drive scope the app currently uses — then opens the Picker in folder-selection mode and runs four checks against the folder you choose:

  1. files.get on the folder itself — is the picked item readable at all?
  2. files.list with 'folderId' in parents — are its direct children visible?
  3. The same query filtered to images — is that enough to actually scan?
  4. The same query one level deeper, into a subfolder — does the grant recurse?

Check 4 is the one that matters most. DDD scans recursively; if the grant stops at the picked folder's immediate children, the restricted scope stays necessary.

Getting an API key: Google Cloud Console → APIs & Services → Credentials → Create credentials → API key. Enable the Google Picker API for the project as well as the Drive API. Restrict the key to http://localhost:8080 if you like — it is not a secret in the way a client secret is, but there is no reason to leave it open.

Nothing is written. Read-only calls only; no delete, no upload, and the app's own stored settings are untouched.
